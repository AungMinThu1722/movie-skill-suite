# Sub-Agent Brief — Delegating Part Runs (videos > 15 minutes)

When `make_frames.py` prints `PLAN: {"mode": "parts", ...}`, the parent
agent must delegate every part. Each part folder is a self-contained visual
work package with global film timestamps. The parent must not view those
frames itself; it collects the part SRTs and merges them.

## Brief template

Fill every `{{...}}` and dispatch the completed brief verbatim:

```
You are a visual-analysis worker for ONE part of a movie. Do exactly what is
written here and do not touch another part.

MOVIE TITLE : {{TITLE}}
YOUR PART   : part {{N}} of {{TOTAL_PARTS}}
FRAMES DIR  : {{FRAMES_DIR}}              (absolute path)
MANIFEST    : {{FRAMES_DIR}}/manifest.json
DIALOGUE    : {{FRAMES_DIR}}/dialogue.txt (or "none — pure visual run")
GAP WINDOWS : {{GAP_WINDOWS}}             (from parts.json gaps_inside, or "none")
SEGMENTS    : {{A}}–{{B}} (the manifest is the source of truth)
LANGUAGE    : {{LANGUAGE_CODE or "determine it yourself per vision-prompt.md"}}
YOUR OUTPUT : {{OUTPUT_SRT}}              (absolute path)
SCRIPT TXT  : {{SCRIPT_TXT}}              (absolute path)
SKILL DIR   : {{SKILL_DIR}}               (absolute path to video-scene-script)

Steps, in order:
1. Read {{SKILL_DIR}}/references/vision-prompt.md and follow it exactly.
2. Read {{FRAMES_DIR}}/manifest.json before any image. Note the part range,
   every segment, frame reason, gap flag, and dialogue_lines field.
3. If {{FRAMES_DIR}}/dialogue.txt exists, read it BEFORE any frame. Treat it
   as plot context and keep a running story summary. Do not read or change
   another part's dialogue file.
4. View EVERY frame in {{FRAMES_DIR}}, one at a time, in timestamp order.
   Note whether each is uniform, scene, gap-uniform, or gap-scene. Never
   write an entry from a filename alone.
5. Write {{SCRIPT_TXT}}: first line `# language: <code>`, then EXACTLY
   {{B}}−{{A}}+1 non-comment lines, one plot-aware line per minute. Use
   1–3 phrases for normal minutes and richer entries up to 4–5 phrases for
   gap minutes when the extra frames show meaningful wordless action.
6. Build the part SRT using make_srt.py only:
     python3 {{SKILL_DIR}}/scripts/make_srt.py \
         {{FRAMES_DIR}}/manifest.json {{SCRIPT_TXT}} --out {{OUTPUT_SRT}}
   Use --bom if the language/script needs it. If the entry count is wrong,
   fix {{SCRIPT_TXT}} and rerun; never hand-edit the SRT.
7. Report exactly one JSON line:
   {"part": {{N}}, "srt": "{{OUTPUT_SRT}}", "entries": <count>,
    "language": "<code>", "ok": true}

Hard rules:
- Handle ONLY part {{N}}. Never touch other part folders, other SRTs, or the
  merge step.
- Read dialogue.txt before frames when it exists; visual facts come from
  frames, while spoken/plot meaning comes from dialogue.txt and readable
  burned-in subtitles.
- Use stable clothing tags. Attach real names only when the dialogue context
  makes the identity confident; otherwise hedge.
- Treat gap minutes as real wordless story sequences, not dead air.
- Use one line per minute and follow vision-prompt.md's phrase style.
- The SRT must be generated by make_srt.py only. Do not type timestamps.
- Do not invent speech, audio, unseen action, or exact plot details.
- Never delete or modify the video, another part's files, or parent files.
```

## Parent checklist

1. Run `mkdir -p .work/parts` before dispatching. Read the `PLAN` JSON and
   fill one brief per part from `parts.json`, including `dialogue` and the
   part's `gaps_inside` values.
2. Dispatch all parts independently, in parallel or sequentially as the
   environment allows. The parent must not inspect part frames.
3. Collect every JSON response. If a part fails or its `entries` count is
   not its manifest segment count, re-dispatch only that part.
4. Verify every `.work/parts/partN.srt` exists and is non-empty before
   merging. The parent, not a worker, runs:

   ```bash
   python3 scripts/merge_srt.py .work/parts/part1.srt .work/parts/part2.srt \
       ... --out "<Movie Name>.srt"
   ```

5. Read the merge output and investigate any timeline gap/overlap warning.
6. After the final SRT is verified, follow `SKILL.md` cleanup and remove
   `.work` without deleting the user's original video.
